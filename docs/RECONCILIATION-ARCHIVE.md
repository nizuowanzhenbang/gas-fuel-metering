# 对账留档与显式重算

日对账页的“按当前输入计算并留档”读取当前表单与数据库，生成新记录。普通“执行对账”和 Excel 导入仍只计算，不自动归档。历史表显示最近 50 条；API 支持 source_id、business_date、limit（1–200）、offset 筛选与翻页。

## 数据与规则

- POST `/api/reconciliation/runs`：使用日对账请求体；有权限且所有站点质量检查通过才写入。
- GET `/api/reconciliation/runs/{id}`：完整 JSON，可通过界面下载。保存气源编号、站点集合、PRIMARY 回路窗口内全部读数（含被排除读数），读数 ID、UTC 时间、累计值的十进制字符串和有效性；不保存与本算法无关的温压等字段。
- 保存业务日窗口、固定时区和日切版本、上游输入、`daily-volume-v1` 算法版本、容差与 FAIL 倍数、结果、创建人/时间。源身份、站点集合与读数用一个 SQL 查询获取，结果只由捕获的数据计算。
- GET `/api/reconciliation/runs/{id}/verify`：校验规范 JSON 的 SHA-256，并用留档输入和规则重放结果，不读取当前计量表或当前业务日设置。
- POST `/api/reconciliation/runs/{id}/recalculate`：`{}` 沿用父记录上游量；也可传正数 `upstream_volume_nm3`。沿用父业务日口径和算法，读取当前计量数据，追加 UUID 新记录与父 ID、厂内计量变化量。允许同一父记录有多个子记录，没有虚构连续修订号。
- 缺边界、表计回退等仍返回 409，失败不追加记录。不自动补算迟到数据。

## 权限与边界

ADMIN、METER_ENG、ACCOUNTANT 可留档/重算；已登录角色可读取/复核。沿用项目单组织 RBAC，不提供租户级隔离。API 没有更新/删除留档端点，但数据库管理员仍可修改；哈希不是签名，不能证明来源真实性或阻止管理员重算哈希。算法 v1 的重放解释器需在后续升级中保留，未知版本拒绝执行。

这是计量核对原型，不写结算表，不执行付款或财务锁单；判定 reason 中“锁单待处置”是沿用数学模块的提示文字，系统不据此执行锁单。示例数据与测试不是现场生产数据。

## 部署与回滚

新增 `reconciliation_runs` 表，不修改旧表。第 8 轮已改为显式 Alembic 迁移，旧的 create_all 留档库经结构检查后可接纳；启动只检查版本，流程见[数据库升级](DATABASE-MIGRATIONS.md)。源表没有级联外键，删除计量数据不会删除历史快照；父子归档使用自引用外键。

回退代码后保留归档表，不自动 DROP，便于以后恢复。单条快照存储完整窗口读数，尚未实现压缩、留存清理或负载上限；大规模历史数据需另外做性能验证。第 8 轮新增真实 PostgreSQL 升级及跨连接持久化回归；不等同完整并发或浏览器端到端验收。

## 面试演示

`python -m pytest backend/tests/test_reconciliation_archive.py -v` 在独立测试库复现：完整首末读数得到 100；故障读数被排除但保留在快照；将原始末值改到 1120，重算得到 120；旧记录仍重放为 100；改变系统时区也不会改变父记录口径；删除原始读数后旧记录仍可复核，新重算则拒绝。可讨论迟到数据、可重放性、显式版本与防篡改边界。
